M82 — SEARCH × Style × TASK

מסמך תכנון · 11.05.2026 · scripts/m82_search_task_table.py

1מטרה

טבלת EDA שמסכמת ארבעה מדדי SEARCH (שניים שטחיים ושניים עמוקים) מול חלוקת Hunter/Busybody שנגזרה מהמסע ב-Wikipedia, ומקרילציה כל מדד SEARCH עם שישה מדדי TASK. הפלט נועד לסקירת מנחים לפני החלטות מידול המשך.

שאלות קונקרטיות
  1. האם מדדי ה-SEARCH העמוקים מ-GBM (% time exploit, N transitions) נותנים יותר סיגנל מהשטחיים (time-to-first reward, inter-reward mean)?
  2. האם אפקט ה-Clumpy vs Diffuse על כל מדד SEARCH תלוי בסגנון ה-Wikipedia (Hunter / Busybody, אופציונלית Dancer)?
  3. אילו מדדי SEARCH מתואמים לאילו מדדי TASK, הן ברמת All והן בתוך כל תת-קבוצה?

2קוהורט

N=132 משתתפים — אותו קוהורט ששימש ב-M81. קריטריוני הכללה (כבר הופעלו upstream):

  • 5 trials של spatial-search ב-data/cleaned/spatial_search/Game.csv
  • GameCondition ב-{Clumpy, Diffuse}
  • מופיע ב-output/m72_new_per_participant.csv (קוהורט post-clean של Wikipedia)

N סופי עשוי להיות מעט נמוך מ-132 אם משתתף חסר באחד מקבצי ה-TASK. נדווח N לכל שורה בטבלת הפלט.

6שיוך לקבוצות

k=2 (Hunter / Busybody)

שימוש חוזר בעמודת style מ-m80_hunter_busybody_per_participant.csv. ללא re-clustering.

k=3 (Hunter / Busybody / Dancer)

התאמה מחדש של KMeans (n_clusters=3, n_init=10, random_state=42) על אותן פיצ'רים מתוקננים [topic_concentration, transition_entropy]. שיוך תוויות:

  • הקלסטר עם topic_concentration ממוצע הכי גבוה = hunter
  • הקלסטר עם topic_concentration ממוצע הכי נמוך = busybody
  • הקלסטר הנותר = dancer

תוויות הסגנון החדשות בפלט m82_per_participant.csv בעמודת style_k3; עמודת style הקיימת תיקרא style_k2.

7סטטיסטיקות פר-תא

הטבלה עם שורה אחת לכל (SEARCH measure × group). הקבוצות הן: {All, Hunter, Busybody} ל-k=2, ו-{All, Hunter, Busybody, Dancer} ל-k=3.

עמודהחישוב
Nספירת משתתפים בתת-קבוצה עם ערך מדד שאינו NaN.
Mean ± SDממוצע מדגם וסטיית תקן של מדד ה-SEARCH בתת-הקבוצה.
Cohen's d (Clumpy − Diffuse)Welch t-test בתוך תת-הקבוצה: מדד SEARCH ב-Clumpy מול Diffuse. גודל אפקט = (mean_clumpy − mean_diffuse) / pooled SD. bold כש-p < .05 (Welch, two-sided).
6 × Spearman ρ (with TASK)Spearman rank correlation בין מדד SEARCH לכל אחד מששת מדדי TASK, בתוך תת-הקבוצה בלבד. מוצג כ-round(ρ × 100). תא צבוע ב-heatmap (אדום=שלילי, כחול=חיובי, רוויה לפי |ρ|). מסגרת שחורה כש-p < .05 (uncorrected). ללא תיקון multiple-comparison — זה EDA.

9פורמט טבלת HTML

שתי טבלאות ה-HTML עוקבות אחרי הפריסה ב-docs/m82_table_mockup.html (כבר נשמר). ספציפית:

  • Light mode, RTL, דף יחיד, טבלה ברוחב מלא.
  • עמודות: Measure, Depth, Group, N, Mean±SD, Cohen's d, ואז שש עמודות קורלציה (אחת לכל מדד TASK).
  • תא Measure משתרע על שורות תת-הקבוצות (rowspan).
  • Shallow: רקע צהבהב לתא ה-measure. Deep: רקע כחלחל.
  • שורות Hunter: צבע תווית קבוצה כחול. Busybody: כתום. Dancer (k=3 בלבד): ירוק.
  • תאי קורלציה: סקלת צבע רציפה, לבן ב-ρ=0. אינטרפולציה בין צבעי עוגן קבועים (ראי לפלטה של m82_table_mockup.html).
  • מסגרת שחורה (outline: 2px solid #1a1a1a) כש-p < .05.
  • Caption מסביר את סקלת הצבע ומשמעות המסגרת, בנוסף ל-N ותאריך.

10מבנה הסקריפט

scripts/m82_search_task_table.py

main():
  1. Load m81_per_trial_features.csv  -> aggregate to per-pid means (4 SEARCH measures)
  2. Load m71, m72, m73                -> merge per-pid (6 TASK measures)
  3. Load m80 styles  (style_k2)
     Refit KMeans k=3 on (topic_concentration, transition_entropy) -> style_k3
  4. Save m82_per_participant.csv
  5. For each k in {2, 3}:
       For each group in {All, hunter, busybody [, dancer]}:
         For each SEARCH measure:
           - compute N, mean, sd
           - Welch t-test Clumpy vs Diffuse -> cohens_d, t, p
           - For each TASK measure: spearmanr -> rho, p
     Save m82_correlations_long.csv, m82_groupstats.csv
     Render m82_search_task_table_k{k}.html (string-based templating,
       no Jinja2 - keep dependency surface small)
  6. Render docs/m82_findings.html populated with computed numbers.

11Out of scope

  • ללא bootstrap CIs — בתאים בודדים זה היה מבלגן את הטבלה. אפשר להוסיף ב-M83+ אם תא ספציפי מצדיק follow-up.
  • ללא interaction tests (למשל style × condition ANOVA). עמודת Cohen's d מחושבת בתוך כל קבוצה, וזה לוכד את הכיוון. אינטראקציות פורמליות שייכות לניתוח confirmatory.
  • ללא תיקון FDR. זה EDA; k=2 לבד מייצר 4×3×6 = 72 קורלציות ו-k=3 מייצר 4×4×6 = 96. BH על האיחוד היה מצמצם יתר על המידה. מסגרת שחורה = nominal p < .05 בלבד, עם הערה ב-caption שזה uncorrected.
  • ללא condition-pooled regression / partial correlations. אם תא נראה חזק נעשה follow-up במייל-סטון ייעודי.
