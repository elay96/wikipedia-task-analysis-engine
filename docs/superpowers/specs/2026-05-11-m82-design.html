M82 - SEARCH measures × Style × TASK correlations

Spec date: 2026-05-11 · Script: scripts/m82_search_task_table.py (planned)

1. Goal

EDA table summarising four SEARCH-task measures (two shallow, two deep) against Hunter/Busybody groupings derived from Wikipedia browsing, and correlating each SEARCH measure with six TASK-side measures. Output is intended for advisor review to inform follow-up modelling decisions.

Concretely we want to answer:

  1. Do the deep GBM-derived SEARCH measures (% time exploit, N transitions) give more signal than the shallow event-based ones (time-to-first reward, inter-reward mean)?
  2. Does the Clumpy vs Diffuse manipulation effect on each SEARCH measure depend on the participant's Wikipedia style (Hunter / Busybody, optionally Dancer)?
  3. Which SEARCH measures correlate with which TASK measures, overall and within each style sub-group?

2. Cohort

N=132 participants - the same cohort used in M81. Inclusion criteria (already applied upstream):

  • 5 spatial-search trials present in data/cleaned/spatial_search/Game.csv
  • GameCondition in {Clumpy, Diffuse}
  • Present in output/m72_new_per_participant.csv (post-clean Wikipedia cohort)

Final N may be slightly below 132 if a participant is missing one of the TASK-side files. We will report N per row of the output table.

4. SEARCH measures (4)

Each measure is one scalar per participant: mean across the 5 trials. All four are already computed per-trial in m81_per_trial_features.csv - this spec does NOT recompute them.

#NameDepthSource column (per-trial)

3% time in exploitdeep pct_time_exploit

Aggregation: mean across the 5 trials, skipping NaN. Participants with all-NaN for a given measure get NaN in the output (and are excluded from that row's statistics).

6. Group assignment

k=2 (Hunter / Busybody)

Reuse the style column from m80_hunter_busybody_per_participant.csv. No re-clustering.

k=3 (Hunter / Busybody / Dancer)

Refit KMeans (n_clusters=3, n_init=10, random_state=42) on the same standardised features [topic_concentration, transition_entropy]. Label assignment:

  • The cluster with the highest mean topic_concentration = hunter
  • The cluster with the lowest mean topic_concentration = busybody
  • The remaining cluster = dancer

Output the new style labels in m82_per_participant.csv as style_k3; the existing style column is renamed to style_k2.

7. Per-cell statistics

The table has one row per (SEARCH measure × group). Groups are: {All, Hunter, Busybody} for k=2, and {All, Hunter, Busybody, Dancer} for k=3.

ColumnComputation
N Count of participants in this sub-group with non-NaN measure value.
Mean ± SD Sample mean and SD of the SEARCH measure in this sub-group.
Cohen's d (Clumpy − Diffuse) Welch t-test within the sub-group: SEARCH measure in Clumpy vs Diffuse. Effect size = (mean_clumpy − mean_diffuse) / pooled SD. Bold when p < .05 (Welch, two-sided).
6 × Spearman ρ (with TASK) Spearman rank correlation between the SEARCH measure and each of the six TASK measures, computed within the sub-group only. Displayed as round(ρ × 100). Cell coloured on heatmap scale (red = negative, blue = positive, saturation by |ρ|). Black outline when p < .05 (uncorrected). No multiple-comparison correction - this is EDA.

9. HTML table format

The two table HTMLs follow the layout shown in docs/m82_table_mockup.html (already saved). Specifically:

  • Light mode, RTL, single page, full-width table.
  • Columns: Measure, Depth, Group, N, Mean±SD, Cohen's d, then six correlation columns (one per TASK measure).
  • Measure cell spans the rows for its sub-groups (rowspan).
  • Shallow measures: yellow-tinted measure-cell background. Deep measures: blue-tinted background.
  • Hunter rows: blue group-label colour. Busybody rows: orange. Dancer rows (k=3 only): green.
  • Correlation cells: continuous colour scale, white at ρ=0. Computed by interpolating between fixed anchor colours (mirror of m82_table_mockup.html's palette).
  • Black outline (outline: 2px solid #1a1a1a) when p < .05.
  • Caption explains the colour scale and the outline meaning, plus sample size and date.

10. Script structure

scripts/m82_search_task_table.py

main():
  1. Load m81_per_trial_features.csv  -> aggregate to per-pid means (4 SEARCH measures)
  2. Load m71, m72, m73                -> merge per-pid (6 TASK measures)
  3. Load m80 styles  (style_k2)
     Refit KMeans k=3 on (topic_concentration, transition_entropy) -> style_k3
  4. Save m82_per_participant.csv
  5. For each k in {2, 3}:
       For each group in {All, hunter, busybody [, dancer]}:
         For each SEARCH measure:
           - compute N, mean, sd
           - Welch t-test Clumpy vs Diffuse -> cohens_d, t, p
           - For each TASK measure: spearmanr -> rho, p
     Save m82_correlations_long.csv, m82_groupstats.csv
     Render m82_search_task_table_k{k}.html (string-based templating,
       no Jinja2 - keep dependency surface small)
  6. Render docs/m82_findings.html populated with computed numbers.

11. Out of scope

  • No bootstrap CIs (single-cell ones would clutter the table). Bootstrap can be added later in M83+ if a specific cell is followed up.
  • No interaction tests (e.g. style × condition ANOVA). The Cohen's d column is computed within each group, which already captures the direction. Formal interactions belong in confirmatory analysis.
  • No FDR correction. EDA; k=2 alone produces 4×3×6 = 72 correlations and k=3 produces 4×4×6 = 96. BH over the joint set would over-shrink. Black outline = nominal p < .05 only, with a caption note that this is uncorrected.
  • No condition-pooled regression / partial correlations. If a cell looks strong we can follow up in a dedicated milestone.

12. Acceptance criteria

  • Both HTML tables open in Chrome/Edge with correct RTL layout and no layout breakage at 1280px width.
  • Every numeric cell has either a finite value or an em-dash ("-") when N<3 in the sub-group.
  • Re-running the script produces byte-identical output (deterministic; KMeans seeded with random_state=42).
  • m82_per_participant.csv contains 132 rows or fewer (post-merge), with the documented columns.
  • m82_findings.html mentions the top-3 absolute-ρ cells per measure and flags any cell with p < .05.
